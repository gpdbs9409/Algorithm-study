# 양궁대회 — 백트래킹

## 1. 문제

[프로그래머스 — 양궁대회](https://school.programmers.co.kr/learn/courses/30/lessons/92342)

### 문제 설명

어피치가 먼저 `n`발의 화살을 쏜 뒤 라이언이 `n`발의 화살을 쏜다.

각 점수 `k`에 대해 더 많은 화살을 맞힌 선수가 해당 점수를 가져간다.

- 어피치와 라이언이 같은 수의 화살을 맞히면 어피치가 점수를 가져간다.
- 두 선수 모두 해당 점수에 화살을 맞히지 않았다면 아무도 점수를 얻지 않는다.
- 같은 점수에 여러 발을 맞혀도 해당 점수만 얻는다.
- 최종 점수가 같은 경우 어피치가 승리한다.

라이언이 가장 큰 점수 차이로 우승할 수 있는 화살 배치를 구한다.

---

# 접근 1

## 1. 라이언의 화살 배치 경우의 수를 모두 구해보자

경우의 수마다 탐색한다고 생각했다.

경우의 수는 라이언의 과녁 배열 조합이며, 각 배열의 합은 `n`이 되어야 한다.

즉,

> `n`개의 화살을 11개의 점수 칸에 어떻게 나누어 넣을 것인가?

를 경우의 수로 생각했다.

---

## 1-1. 어떻게 구현할까?

배열의 첫 번째 요소부터 두 번째 요소로 이동하면서 남은 화살을 갱신하는 방법을 생각했다.

각 칸마다 넣을 수 있는 화살의 수를 결정하면서 배열을 만들어야 한다.

하지만 각 칸에 들어갈 화살의 수를 하나씩 모두 탐색하면 경우의 수가 너무 많아질 것 같았다.

```text
첫 번째 칸에 몇 발?
→ 두 번째 칸에 몇 발?
→ 세 번째 칸에 몇 발?
→ ...
```

각 배열의 합이 `n`을 넘지 않도록 확인하면서 탐색해야 한다.

---

## 1-2. 백트래킹을 생각

결국 화살을 어떻게 분배할지 여러 경우의 수를 탐색해야 한다.

하지만 이미 사용한 화살의 합이 `n`을 넘어가는 경우에는 그 뒤를 더 탐색할 필요가 없다.

따라서 모든 경우를 무조건 끝까지 탐색하기보다는,

> 조건에 맞지 않는 경우 더 이상 탐색하지 않는 가지치기

를 사용할 수 있다고 생각했다.

그래서 백트래킹을 이용하는 방향을 생각했다.

---

## 1-3. 백트래킹 기본 구조 생각하기

백트래킹의 기본 구조는

```text
선택
→ 재귀
→ 선택 취소
→ 다른 경우 탐색
```

이다.

라이언의 화살 배열을 하나씩 채우면서 재귀적으로 다음 칸으로 이동한다.

이때 지금까지 사용한 화살의 합을 같이 넘겨준다.

```python
lion_score = [0] * 11

def backtracking(index, total):
    next_score = total + now

    if next_score < 10:
        lion_score.append(now)

    backtracking(index + 1, next_score)

# now는 1과 n-total 사이의 값
```

여기서 `now`는

> 현재 칸에 몇 발의 화살을 넣을 것인가?

를 의미한다.

---

## 2. 완성된 경우마다 점수 계산

라이언의 화살 배열 하나가 완성되면 각 점수 칸을 순회하면서 라이언과 어피치의 총점을 계산한다.

```text
라이언 화살 > 어피치 화살
→ 라이언이 해당 점수를 획득

라이언 화살 <= 어피치 화살
→ 어피치가 해당 점수를 획득

단, 둘 다 0발이면 아무도 점수를 얻지 않음
```

각 경우의 수마다 라이언과 어피치의 점수를 계산하고 비교한다.

---

## 3. 가장 좋은 배열 갱신

라이언이 이기는 경우에만 현재 화살 배열을 후보로 사용한다.

기존 후보보다 더 큰 점수 차이로 이긴다면 현재 배열로 정답을 갱신한다.

---

# 접근 2

접근 1에서는

> 현재 칸에 화살을 몇 발 넣을까?

를 기준으로 경우의 수를 만들려고 했다.

하지만 어피치의 화살 배열 `info`가 이미 주어져 있다는 점을 이용하면 경우의 수를 훨씬 줄일 수 있다.

---

## 1. 모든 화살 개수를 탐색할 필요가 없다

어떤 점수에서 어피치가 `a`발을 맞혔다고 하자.

라이언이 해당 점수를 가져오려면 최소한

```python
a + 1
```

발이 필요하다.

어피치와 같은 수의 화살을 맞히면 어피치가 점수를 가져가기 때문이다.

예를 들어 어피치가 10점에 2발을 맞혔다면,

```text
라이언 0발 → 점수 못 먹음
라이언 1발 → 점수 못 먹음
라이언 2발 → 동점이므로 점수 못 먹음

라이언 3발 → 점수 획득

라이언 4발 → 점수 획득
라이언 5발 → 점수 획득
...
```

하지만 3발을 쏘든 4발을 쏘든 라이언이 얻는 점수는 똑같이 10점이다.

따라서 4발 이상을 쏘는 경우까지 탐색할 필요가 없다.

결국 현재 점수에서 의미 있는 선택은 두 가지로 줄어든다.

```text
1. 점수를 포기한다
   → 0발

2. 점수를 먹는다
   → info[idx] + 1발
```

즉,

> `0 ~ n`발 중 몇 발을 넣을까?

가 아니라

> 이 점수를 먹을까 / 포기할까?

로 관점을 바꿀 수 있다.

---

## 2. 재귀를 두 갈래로 뻗는다

현재 점수를 먹기 위해 필요한 화살을 다음과 같이 구한다.

```python
now = info[idx] + 1
```

현재 점수를 포기하는 경우에는 화살을 사용하지 않는다.

```python
score(idx + 1, total)
```

현재 점수를 먹는 경우에는 `now`만큼 화살을 사용한다.

```python
score(idx + 1, total + now)
```

따라서 하나의 상태에서 경우의 수가 다음과 같이 갈라진다.

```text
                    현재 점수
                   /        \
                포기          획득
                 |             |
        total 그대로      total + now
```

---

## 3. 먹는 경우에만 조건을 확인한다

처음에는 다음과 같이 생각했다.

```text
화살이 부족하면
→ 안 먹는 경우

화살이 충분하면
→ 안 먹는 경우
→ 먹는 경우
```

하지만 `안 먹는 경우`는 화살이 충분한지와 관계없이 항상 가능하다.

따라서 안 먹는 재귀는 항상 호출하면 된다.

```python
score(idx + 1, total)
```

그리고 먹는 경우에만 조건을 확인한다.

```python
if total + now <= n:
    score(idx + 1, total + now)
```

즉,

```python
score(idx + 1, total)

if total + now <= n:
    score(idx + 1, total + now)
```

와 같은 형태로 경우의 수 트리를 만들 수 있다.

`total + now > n`인 경우에는 먹는 방향의 재귀를 호출하지 않는다.

→ 불가능한 경우를 더 탐색하지 않으므로 가지치기가 된다.

---

## 4. 라이언의 배열에도 선택을 기록해야 한다

단순히 `total`만 변경해서 재귀를 호출하면 현재 라이언이 어떤 점수들을 선택했는지 알 수 없다.

따라서 현재 점수를 먹기로 선택했다면 라이언의 배열에도 기록한다.

```python
lion_score[idx] = now
```

그 상태에서 다음 재귀를 호출한다.

```python
score(idx + 1, total + now)
```

그리고 해당 경우의 탐색이 끝났다면 다시 원래 상태로 복구한다.

```python
lion_score[idx] = 0
```

즉 백트래킹의

```text
선택
→ 재귀
→ 선택 취소
```

구조가 된다.

---

# sol

```python
def solution(n, info):
    answer = [-1]

    lion_score = [0] * 11
    max_diff = 0

    def score(idx, total):
        nonlocal answer, max_diff

        # 11개 점수를 모두 결정한 경우
        if idx == 11:

            # 남은 화살은 전부 0점에 사용
            lion_score[10] += n - total

            lion_total = 0
            apeach_total = 0

            # 라이언 / 어피치 점수 계산
            for i in range(11):
                point = 10 - i

                if lion_score[i] > info[i]:
                    lion_total += point

                elif info[i] > 0:
                    apeach_total += point

            diff = lion_total - apeach_total

            # 라이언이 이겼을 때
            if diff > 0:

                # 기존보다 더 큰 점수 차이
                if diff > max_diff:
                    max_diff = diff
                    answer = lion_score[:]

                # 같은 점수 차이 → 낮은 점수를 더 많이 맞힌 경우
                elif diff == max_diff:
                    for i in range(10, -1, -1):
                        if lion_score[i] > answer[i]:
                            answer = lion_score[:]
                            break

                        elif lion_score[i] < answer[i]:
                            break

            # 0점에 넣었던 남은 화살 복구
            lion_score[10] -= n - total

            return

        # 현재 점수를 먹기 위해 필요한 화살
        now = info[idx] + 1

        # 1. 현재 점수를 먹지 않는 경우
        score(idx + 1, total)

        # 2. 현재 점수를 먹는 경우
        if total + now <= n:
            lion_score[idx] = now

            score(idx + 1, total + now)

            # 백트래킹: 선택 취소
            lion_score[idx] = 0

    score(0, 0)

    return answer
```
