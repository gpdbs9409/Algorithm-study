# 피로도 (Lv2)

# 문제 설명

```text
XX게임에는 피로도 시스템(0 이상의 정수로 표현합니다)이 있으며,
일정 피로도를 사용해서 던전을 탐험할 수 있습니다.

각 던전마다 탐험을 시작하기 위해 필요한 "최소 필요 피로도"와
던전 탐험을 마쳤을 때 소모되는 "소모 피로도"가 있습니다.

예를 들어 "최소 필요 피로도"가 80, "소모 피로도"가 20인 던전을 탐험하기 위해서는
유저의 현재 남은 피로도가 80 이상이어야 하며,
던전을 탐험한 후에는 피로도 20이 소모됩니다.

하루에 한 번씩 탐험할 수 있는 던전이 여러 개 있을 때,
한 유저가 탐험할 수 있는 최대 던전 수를 구해야 합니다.

현재 피로도 k와
각 던전의 [최소 필요 피로도, 소모 피로도]가 담긴 2차원 배열 dungeons가 주어질 때,
유저가 탐험할 수 있는 최대 던전 수를 return 합니다.
```

---

# 접근

1. 던전의 방문 순서에 따라 남은 피로도가 달라지고,
   그 결과 이후에 방문할 수 있는 던전도 달라진다.

   예를 들어 같은 던전들이 주어져 있어도

   ```text
   A → B → C
   A → C → B
   ```

   처럼 어떤 순서로 방문했는지에 따라 중간에 남아 있는 피로도가 달라진다.

   따라서 가능한 던전 방문 순서를 여러 가지로 탐색해야 한다.

2. 던전의 개수가 최대 8개로 작기 때문에
   가능한 모든 방문 순서를 확인하는 완전탐색이 가능하다.

   가장 직접적인 방법은 `permutations`를 사용해서
   가능한 모든 던전 방문 순서를 만든 뒤 각각 확인하는 것이다.

3. 같은 탐색을 **DFS + 백트래킹**으로도 구현할 수 있다.

   백트래킹은 가능한 선택을 하나씩 탐색하면서,
   현재 조건에서 선택할 수 없는 경우에는 해당 선택을 진행하지 않고
   이전 상태로 돌아와 다른 선택을 탐색하는 방식이다.

   이 문제에서는 **지금까지 어떤 던전을 선택했는지가 중요하다.**

   방문 순서에 따라 피로도 소모 과정이 달라지고,
   그 결과 이후에 방문할 수 있는 던전이 달라지기 때문이다.

4. 따라서 하나의 던전을 선택했다면 방문 처리한 뒤 다음 던전을 탐색하고,
   해당 경로의 탐색이 끝나면 이전 상태로 돌아와 방문 처리를 취소해야 한다.

   ```text
   던전 선택
   → 방문 처리
   → DFS로 다음 선택 탐색
   → 이전 호출로 돌아옴
   → 방문 처리 취소
   → 다른 던전 선택
   ```

5. 재귀 DFS를 사용하면 이전 함수 호출의 상태가 콜스택(Call Stack)에 저장된다.

   따라서 현재 경로를 끝까지 탐색한 뒤 이전 호출로 돌아와
   상태를 복구하고 다른 선택지를 탐색할 수 있다.

# sol1 - permutations를 이용한 완전탐색

```python
from itertools import permutations

def solution(k, dungeons):
    answer = 0

    for dungeon_order in permutations(dungeons):
        fatigue = k
        count = 0

        for required, cost in dungeon_order:
            if fatigue >= required:
                fatigue -= cost
                count += 1
            else:
                break

        answer = max(answer, count)

    return answer
```

## sol1 풀이

`permutations(dungeons)`를 사용해서
가능한 던전 방문 순서를 전부 만들어본다.

예를 들어 던전이

```text
A, B, C
```

세 개라면

```text
A → B → C
A → C → B
B → A → C
B → C → A
C → A → B
C → B → A
```

총 `3! = 6`개의 순서를 확인한다.

각 순열을 확인할 때마다 현재 피로도를 처음 상태인 `k`로 초기화한다.

```python
fatigue = k
```

그리고 해당 순서대로 던전을 방문한다.

```python
if fatigue >= required:
    fatigue -= cost
    count += 1
```

현재 피로도가 최소 필요 피로도보다 작다면
해당 순서에서는 더 이상 다음 던전으로 진행할 수 없으므로 탐색을 종료한다.

```python
else:
    break
```

각 방문 순서에서 탐험할 수 있었던 던전 개수를 구하고,
그중 최댓값을 저장한다.

```python
answer = max(answer, count)
```

즉,

```text
가능한 방문 순서를 전부 생성
→ 각 순서대로 던전 방문
→ 방문 가능한 던전 수 계산
→ 최댓값 저장
```

하는 완전탐색 방식이다.

# sol2 - DFS + 백트래킹

```python
def solution(k, dungeons):
    n = len(dungeons)
    visited = [False] * n

    def dfs(fatigue, count):
        max_count = count

        for i in range(n):
            required, cost = dungeons[i]

            if not visited[i] and fatigue >= required:
                visited[i] = True

                max_count = max(
                    max_count,
                    dfs(fatigue - cost, count + 1)
                )

                visited[i] = False

        return max_count

    return dfs(k, 0)
```

## sol2 풀이

DFS의 인자는

```python
dfs(fatigue, count)
```

로 두었다.

각각

```text
fatigue = 현재 남아 있는 피로도
count   = 지금까지 방문한 던전 개수
```

를 의미한다.

현재 상태에서 모든 던전을 확인한다.

```python
for i in range(n):
```

아직 방문하지 않았고,

```python
not visited[i]
```

현재 피로도로 입장할 수 있다면,

```python
fatigue >= required
```

해당 던전을 선택한다.

```python
visited[i] = True
```

그리고 해당 던전의 소모 피로도를 차감하고,
방문한 던전 수를 1 증가시킨 상태로 다음 DFS를 호출한다.

```python
dfs(fatigue - cost, count + 1)
```

예를 들어 현재 상태에서 A를 선택했다면

```text
현재 상태
   ↓
A 선택
   ↓
A를 선택한 상태에서
B, C, D 중 다음 던전 선택
```

처럼 한 경로를 계속 깊게 탐색한다.

해당 경로의 탐색이 끝나면 이전 DFS 호출로 돌아온다.

이때

```python
visited[i] = False
```

로 방문 상태를 다시 복구한다.

예를 들어

```text
A → B → C
```

경로를 탐색했다고 해서 B와 C를 영원히 방문 처리하면 안 된다.

다음에는

```text
A → C → B
```

또는

```text
B → A → C
```

같은 다른 방문 순서에서도 해당 던전들을 선택해야 하기 때문이다.

따라서

```python
visited[i] = True

dfs(...)

visited[i] = False
```

의

```text
선택
→ 탐색
→ 선택 취소
```

과정이 백트래킹의 핵심이다.

---

# sol1과 sol2의 관계

두 풀이의 핵심은 같다.

둘 다 **가능한 던전 방문 순서를 탐색한다.**

### permutations

```text
가능한 순서를 먼저 만들어놓음

A → B → C
A → C → B
B → A → C
...
```

그 후 각각의 순서를 확인한다.

### DFS + 백트래킹

```text
A 선택
→ B 선택
   → C 선택
→ B 선택 취소
→ C 선택
   → B 선택
...
```

순서를 미리 만들어놓는 대신
DFS를 통해 선택하면서 방문 순서를 만들어간다.

즉,

```text
permutations
= 가능한 순서를 직접 생성해서 완전탐색

DFS + 백트래킹
= 선택 → 재귀 → 복구를 반복하면서 가능한 순서를 탐색
```

이라고 이해할 수 있다.

---

# 시간복잡도

**O(N! × N)**

던전이 N개라면 가능한 방문 순서는 최대

```text
N!
```

개이다.

`permutations` 풀이에서는 각 순열마다
최대 N개의 던전을 확인한다.

따라서 시간복잡도는

```text
O(N! × N)
```

이다.

이 문제에서는 던전의 개수가 최대 8개이므로

```text
8! = 40,320
```

정도의 방문 순서를 확인하면 되기 때문에 완전탐색이 가능하다.

DFS + 백트래킹 역시 가능한 던전 방문 순서를 탐색하므로
최악의 경우 팩토리얼 계열의 시간복잡도를 가진다.

---

# 공간복잡도

## sol1 - permutations

`permutations`는 순열을 하나씩 생성하며,
현재 순열의 크기는 N이다.

따라서 추가적으로 사용하는 공간은 **O(N)**이다.

## sol2 - DFS + 백트래킹

```python
visited = [False] * n
```

이므로 `visited`가 O(N)의 공간을 사용한다.

또한 DFS의 재귀 깊이는 최대 N이다.

```text
dfs(...)
 → dfs(...)
   → dfs(...)
     → ...
```

따라서 콜스택 역시 O(N)의 공간을 사용한다.

```text
visited O(N)
+ call stack O(N)
= O(N)
```

최종 추가 공간복잡도는 **O(N)**이다.

# 배운점

1. 백트래킹은 DFS를 이용해 가능한 선택을 탐색하면서,
   현재 선택을 끝까지 확인한 뒤 이전 상태로 돌아와 다른 선택을 탐색하는 방식이다.

   핵심 흐름은

   ```text
   선택
   → 재귀 탐색
   → 상태 복구
   → 다른 선택
   ```

   이다.

2. 이 문제에서는 **방문 경로, 즉 어떤 순서로 던전을 선택했는지가 중요하다.**

   방문 순서에 따라 피로도가 소모되는 과정이 달라지고,
   그 결과 이후에 방문할 수 있는 던전이 달라지기 때문이다.

3. 일반적인 그래프 DFS에서는 한 번 방문한 노드를 다시 방문할 필요가 없기 때문에
   `visited`를 다시 `False`로 변경하지 않는다.

   ```python
   visited[node] = True
   dfs(next_node)
   ```

   반면 백트래킹에서는 다른 선택 경로에서 같은 요소를 다시 선택해야 할 수 있다.

   따라서 현재 경로의 탐색이 끝나면

   ```python
   visited[i] = False
   ```

   로 상태를 복구해야 한다.

4. 백트래킹에서 중요한 것은 단순히 조건을 만족했을 때 탐색을 종료하는 것이 아니다.

   현재 선택이 조건에 맞지 않으면 **그 선택으로 이어지는 경로는 더 탐색하지 않고**,
   이전 상태로 돌아가 다른 선택을 탐색한다.

5. 재귀 DFS에서는 함수 호출 정보가 콜스택에 저장된다.

   따라서 별도의 Stack 자료구조를 직접 만들지 않아도
   한 경로를 깊게 탐색한 뒤 이전 호출로 돌아갈 수 있다.

6. `permutations`와 DFS + 백트래킹은 완전히 다른 아이디어가 아니다.

   이 문제에서는 둘 다 가능한 던전 방문 순서를 탐색한다.

   ```text
   permutations
   → 순서를 직접 만들어서 확인

   DFS + 백트래킹
   → 선택하면서 순서를 만들어서 확인
   ```

7. BFS와 백트래킹은 모두 상태를 탐색할 수 있지만,
   `visited`의 의미가 다를 수 있다.

   BFS 최단거리에서는 이미 방문한 상태를 다시 탐색할 필요가 없으므로
   방문 상태를 유지한다.

   반면 백트래킹에서는 현재 선택 경로가 끝난 뒤 상태를 복구해서
   다른 선택 경로에서도 같은 요소를 사용할 수 있도록 해야 한다.

# 한 줄 정리

```text
방문 순서에 따라 남은 피로도와 다음 선택이 달라짐
→ 가능한 방문 순서를 탐색해야 함
→ permutations 완전탐색 또는 DFS + 백트래킹
→ 백트래킹은 선택 → 재귀 → 복구 → 다른 선택
```
