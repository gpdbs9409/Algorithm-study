# 문제: 피로도 (Lv2)

## 문제 설명

```text
XX게임에는 피로도 시스템(0 이상의 정수로 표현합니다)이 있으며,
일정 피로도를 사용해서 던전을 탐험할 수 있습니다.

각 던전마다 탐험을 시작하기 위해 필요한 "최소 필요 피로도"와
던전 탐험을 마쳤을 때 소모되는 "소모 피로도"가 있습니다.

예를 들어 "최소 필요 피로도"가 80, "소모 피로도"가 20인 던전을 탐험하기 위해서는
유저의 현재 남은 피로도가 80 이상이어야 하며,
던전을 탐험한 후에는 피로도 20이 소모됩니다.

하루에 한 번씩 탐험할 수 있는 던전이 여러 개 있을 때,
한 유저가 탐험할 수 있는 최대 던전 수를 구해야 합니다.

현재 피로도 k와
각 던전의 [최소 필요 피로도, 소모 피로도]가 담긴 2차원 배열 dungeons가 주어질 때,
유저가 탐험할 수 있는 최대 던전 수를 return 합니다.
```

---

# 접근

1. 처음에는 피로도가 높은 던전부터 가거나, 소모 피로도가 작은 던전부터 가는 방식의 그리디를 생각할 수 있다.

   하지만 어떤 던전을 먼저 방문하느냐에 따라 이후 방문할 수 있는 던전이 달라지기 때문에
   단순히 하나의 기준으로 정렬해서 해결하기 어렵다.

2. 던전의 개수가 최대 8개로 매우 작다.

   따라서 가능한 던전 방문 순서를 전부 확인할 수 있다.

3. 현재 피로도가 해당 던전의 `최소 필요 피로도` 이상이라면 탐험할 수 있다.

   ```python
   if fatigue >= required:
   ```

   탐험한 후에는

   ```python
   fatigue -= cost
   ```

   로 현재 피로도를 갱신한다.

4. 모든 가능한 방문 순서를 확인하면서 실제로 방문할 수 있었던 던전 개수의 최댓값을 구한다.

즉,

```text
가능한 던전 순서를 모두 만들어본다
→ 해당 순서대로 실제 입장 가능한지 확인한다
→ 방문한 던전 수를 센다
→ 그중 최댓값을 반환한다
```

---

# sol1

처음에는 피로도가 많이 필요한 던전부터 방문하면 된다고 생각했다.

```python
def solution(k, dungeons):
    answer = 0

    dungeons.sort(reverse=True)

    for required, cost in dungeons:
        if k >= required:
            k -= cost
            answer += 1

    return answer
```

## sol1의 문제점

단순히 최소 필요 피로도가 높은 던전부터 방문하는 것이 항상 최적이라는 보장이 없다.

던전에는

```text
최소 필요 피로도
소모 피로도
```

두 가지 조건이 동시에 존재한다.

따라서 최소 필요 피로도가 높더라도 소모 피로도가 매우 클 수 있고,
그 던전을 먼저 방문하면서 이후에 방문할 수 있었던 다른 던전들을 방문하지 못하게 될 수 있다.

즉 이 문제는 특정 기준으로 정렬해서 하나의 순서만 확인하는 것이 아니라,
**던전 방문 순서 자체를 여러 가지로 확인해야 한다.**

---

# sol2 - 순열 이용

던전의 개수가 최대 8개이므로 가능한 모든 던전 방문 순서를 만들어서 확인할 수 있다.

```python
from itertools import permutations

def solution(k, dungeons):
    answer = 0

    for dungeon_order in permutations(dungeons):
        fatigue = k
        count = 0

        for required, cost in dungeon_order:
            if fatigue >= required:
                fatigue -= cost
                count += 1
            else:
                break

        answer = max(answer, count)

    return answer
```

## 풀이

`permutations(dungeons)`를 사용하면 가능한 던전 방문 순서를 전부 만들 수 있다.

예를 들어 던전이

```text
A, B, C
```

세 개라면

```text
A → B → C
A → C → B
B → A → C
B → C → A
C → A → B
C → B → A
```

총 `3! = 6`개의 순서를 확인한다.

각 순열마다 피로도를 처음 상태인 `k`로 초기화한다.

```python
fatigue = k
```

그리고 해당 순서대로 던전을 확인한다.

```python
if fatigue >= required:
    fatigue -= cost
    count += 1
```

현재 피로도가 최소 필요 피로도보다 작으면 해당 던전에 들어갈 수 없다.

```python
else:
    break
```

현재 순열에서는 뒤의 던전보다 현재 던전을 먼저 방문하기로 정해놓은 것이므로
여기서 탐험을 종료하고 다음 순열을 확인한다.

마지막으로 모든 순열에서 얻은 `count` 중 최댓값을 저장한다.

```python
answer = max(answer, count)
```

# sol3 - DFS / 백트래킹

순열을 직접 생성하지 않고 DFS를 이용해서
"다음에 어느 던전을 갈 것인지"를 하나씩 선택하는 방식으로도 풀 수 있다.

```python
def solution(k, dungeons):
    n = len(dungeons)
    visited = [False] * n

    def dfs(fatigue, count):
        max_count = count

        for i in range(n):
            required, cost = dungeons[i]

            if not visited[i] and fatigue >= required:
                visited[i] = True

                max_count = max(
                    max_count,
                    dfs(fatigue - cost, count + 1)
                )

                visited[i] = False

        return max_count

    return dfs(k, 0)
```

## DFS의 의미

DFS의 인자는

```python
dfs(fatigue, count)
```

이다.

각각

```text
fatigue = 현재 남아 있는 피로도
count   = 지금까지 방문한 던전 개수
```

를 의미한다.

현재 상태에서 모든 던전을 확인한다.

```python
for i in range(n):
```

아직 방문하지 않았고,

```python
not visited[i]
```

현재 피로도로 입장할 수 있다면,

```python
fatigue >= required
```

그 던전을 선택한다.

```python
visited[i] = True
```

그리고 해당 던전을 방문한 상태로 다음 DFS를 호출한다.

```python
dfs(fatigue - cost, count + 1)
```

탐색이 끝나고 돌아오면

```python
visited[i] = False
```

로 원상복구한다.

이 부분이 백트래킹의 핵심이다.

```text
던전 선택
→ visited = True
→ 다음 경우 탐색
→ 돌아옴
→ visited = False
→ 다른 던전을 선택해서 다시 탐색
```

---

# 시간복잡도

**O(N! × N)**  
(순열 풀이 기준)

던전이 N개일 때 가능한 방문 순서는

```text
N!
```

개이다.

각 순열마다 최대 N개의 던전을 확인하므로

```text
O(N! × N)
```

이다.

이 문제에서는 던전의 개수가 최대 8개이므로 완전탐색이 가능하다.

```text
8! = 40,320
```

이고 각 순열에서 최대 8개의 던전을 확인하므로 충분히 처리할 수 있다.

DFS/백트래킹 풀이 역시 가능한 던전 방문 순서를 탐색하므로
최악의 경우 같은 계열의 팩토리얼 시간복잡도를 가진다.

---

# 공간복잡도

## 순열 풀이

순열을 하나씩 순회하면서 현재 순서와 몇 개의 변수만 사용한다.

다만 `itertools.permutations`가 생성하는 각 순열의 크기가 O(N)이므로
추가적으로 필요한 공간은 O(N) 수준이다.

## DFS / 백트래킹 풀이

```python
visited = [False] * n
```

이므로 `visited`가 O(N)의 공간을 사용한다.

또한 DFS의 재귀 깊이는 최대 N이다.

```text
dfs(0)
 → dfs(1)
   → dfs(2)
     → ...
       → dfs(N)
```

따라서 콜스택도 O(N)의 공간을 사용한다.

```text
visited O(N)
+ recursion stack O(N)
= O(N)
```

최종 추가 공간복잡도는 **O(N)**이다.

# 배운점

1. 던전의 방문 순서에 따라 결과가 달라지는 문제에서는 단순한 그리디로 해결할 수 있는지 먼저 확인해야 한다.

   이 문제에서는 최소 필요 피로도와 소모 피로도라는 두 조건이 있기 때문에
   단순히 하나의 기준으로 정렬하는 것만으로 최적의 순서를 보장할 수 없다.

2. 입력 크기가 매우 작다면 완전탐색을 고려할 수 있다.

   던전의 개수가 최대 8개이므로 가능한 모든 순서인 `8!`을 직접 탐색해도 충분하다.

3. `permutations`는 가능한 순서를 직접 만들어주는 방법이고,
   DFS + 백트래킹은 그 순서를 재귀적으로 하나씩 만들어가는 방법이라고 이해했다.

```text
permutations
→ 가능한 순서를 미리 만들어서 각각 확인

DFS + 백트래킹
→ 하나 선택
→ 다음 하나 선택
→ 끝까지 탐색
→ 되돌아와서 다른 선택
```

결국 둘 다 **가능한 던전 방문 순서를 탐색한다는 핵심 아이디어는 같다.**

4. 백트래킹에서는 `visited`를 다시 `False`로 돌려놓는 과정이 중요하다.

```python
visited[i] = True
dfs(...)
visited[i] = False
```

현재 경우의 탐색이 끝난 뒤 방문 상태를 복구해야
다른 경우의 수에서는 해당 던전을 다시 선택할 수 있다.

5. DFS에서 반드시 `nonlocal answer`을 사용할 필요는 없다.

각 DFS가 현재 상태에서 얻을 수 있는 최대 방문 횟수를 `return`하고,
부모 호출에서

```python
max_count = max(max_count, dfs(...))
```

형태로 결과를 받아 합칠 수 있다.

---

한 줄 정리:

**던전 순서에 따라 결과가 달라지고 N이 작다 → 모든 순서 탐색 → 순열 또는 DFS/백트래킹**
