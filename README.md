## ✅ 참여 방법

1. 이 저장소를 Fork 합니다.
2. Fork한 저장소에 본인 이름으로 폴더를 생성합니다.
3. 해당 주차에 풀기로 한 문제의 소스코드를 본인 폴더에 업로드합니다.
4. 원본 저장소로 Pull Request를 생성합니다.
5. 다른 스터디원의 PR을 확인하고 자유롭게 코드리뷰를 진행합니다. (선택)

### 소스코드 파일명

파일명은 자유롭게 작성합니다.

형식은 자유롭게 작성합니다.

가능하다면 아래 내용을 간단히 작성해주세요.

- 이번 주 문제의 알고리즘 유형
- 가장 어려웠던 문제와 어려웠던 부분
- 문제를 풀며 새롭게 알게 된 점
- 이번 주 문제 풀이에 대한 간단한 회고 등등.. 리드미 최하단 "스터디에서 얘기해볼것" 참고해주세요

특정 코드 라인에 직접 리뷰를 남겨도 되고,
PR 전체에 대한 코멘트로 작성해도 됩니다.

# 💬 스터디에서 이야기해볼 것

단순히 정답 코드를 공유하는 것보다
**어떤 생각을 거쳐 해당 풀이에 도달했는지**를 공유하는 것을 목표로 합니다.

### 1. 문제 접근

문제를 처음 읽었을 때부터 풀이 방법을 결정하기까지의 사고 과정을 공유합니다.

예시:

- 문제에서 어떤 조건을 중요하게 봤는지
- 어떤 알고리즘을 떠올렸는지
- 왜 해당 알고리즘을 선택했는지
- 처음 생각했던 접근이 틀렸다면 어디에서 문제가 생겼는지

### 2. 문제 코드

최종적으로 작성한 코드를 공유합니다.

풀이에 실패했더라도 실패한 코드와 실패 이유를 간단하게 공유해도 좋습니다.

다른 풀이 또는 자료를 참고했다면 참고한 링크를 함께 남깁니다.

### 3. 코드 흐름 설명

나중에 코드를 다시 봤을 때 이해하기 어려울 것 같은 부분은
간단하게 코드의 흐름을 설명합니다.

코드 자체로 의도가 드러날 수 있도록 작성하고,
불필요한 주석은 최대한 줄이는 것을 권장합니다.

### 4. 새롭게 배운 내용

문제를 풀면서 새롭게 알게 된 내용을 자유롭게 기록합니다.

예시:

- 새로운 Python 문법
- 자료구조 사용법
- 시간복잡도
- 알고리즘 패턴
- 기존 풀이보다 효율적인 방법

### 5. 한줄평

문제를 풀고 느낀 점을 간단하게 작성합니다.

예시:

- 어떤 접근은 좋았지만 어떤 부분이 아쉬웠는지
- 비슷한 유형을 더 풀어보면 좋을 것 같은지
- 처음에는 어떤 알고리즘이라고 생각했는데 실제로는 무엇이었는지
- 다음에 같은 유형을 만났을 때 기억하고 싶은 점
